01 · 先给两个问题明确答案

论文主线聚焦人类语音；平台可以扩展多种声音。

建议现在锁定：主轨道为说话声、持续元音、DDK等构音发声任务；咳嗽/呼吸另设扩展轨道；心肺听诊音暂不进入主论文基准榜。平台接口保留声音类型字段，日后支持听诊音不需重写训练/评价框架，但其任务协议必须另注册。

范围包含什么本阶段怎么处理为什么
speech_core朗读、单词、命令词、访谈/描述、持续元音、DDK优先做完整基准与后两块研究与你的“疾病语音”主线一致，输入与生理产生过程相对接近；也仍需按任务分层。
respiratory_extension从口鼻采集的咳嗽和呼吸声；Coswara中语音部分可另进主轨道先存元数据与Adapter扩展点，不作为当前施工前提模型与患者标签仍可评测，但与语言/认知任务的信息机制不同，额外需领域基线。
auscultation_extension胸壁心音/肺音，如ICBHI、KAUH不进speech_core；以后有资源再开独立套件声音通道、频带、事件分段和评价单位不同，混榜难解释。
exclude_main家禽、临床模拟人、只有特征表/代码的记录保留资产台账，不进入原音频患者主榜不是说明它们没价值，而是不支撑当前主结论。

“MLP或CNN听不了听诊音”不是正确理由：它们可以针对数值特征/时频图训练分类器，是否有效需实验。应向评审解释的是研究范围、输入适配与证据边界，而不是把一种架构理解为天生只会听人说话。不同数据集各自训练相同结构，和训练一个共享模型识别全部声音，也是两种完全不同的实验。

OPERA已有呼吸声学的领域基准，可作为以后扩展的参照；这说明扩展可行，不代表现在必须把所有声音都纳入。[R4]只聚焦语音并不妨碍多疾病，PD、抑郁、认知障碍、构音与嗓音任务已经覆盖不同目标。

今天可以开始：用现有原始目录中的EATD和Parkinson_KCL_2017做两个Adapter，先跑同一个MLP＋统一指标闭环。MDVR朗读子目录已清楚，比继续等未在服务器发现的SVD更贴近现实。EasyCall为第三个适配候选。
02 · 新附件改变了哪些判断

这是一份文件结构快照，还不是最终数据审计。

本轮完整解析了服务器HTML中的46个原始目录卡片、27个整理目录卡片，并读取审查XLSX的67条记录。正文只以父级dataset作为本轮主要数据入口；整理目录仅用于发现旧映射风险，不将其与父级相加。

服务器报告称：父级46目录、389,084个被识别音频文件，30目录检出音频、16未检出；整理侧27目录、421,547个音频。这是报告声称的扫描数，不是本次重新访问服务器实测，也不是独立人数或独立原始录音数。

附件里的具体信号应怎样解释这次产品要增加什么
EATD：原972文件/162“标签”，每人员目录6个文件；fresh485162是人员目录组，不是162个疾病类别；原始与_out版本同时存在。162×3=486是完整三任务单版本的预期核对数，不是已确认有效数。区分directory_group_count与target_class_count；每人按命名配对3原始/3处理版本，记录缺失，不直接用485重命名文件。
Parkinson_KCL_2017：ReadText/HC21、ReadText/PD16；对话HC21，其余PD文件朗读部分有37条文件，适合作为启动任务；37个独立人仍需核对完整ID和重复。明确ReadText为任务筛选；同ID不同录音任务仍同组，不把任务名当疾病类别。
HLS_CMDS含__MACOSX和._H0001.wav等扩展名为.wav不代表能解码；可能是macOS资源旁文件。不是1070个有效声音样本。发现阶段列全部文件类型，解码审计排除._*、__MACOSX与无效文件并保留原因。
父级COUGHVID_V3/VOICED未检出音频，Coswara有压缩包未检出支持格式 ≠ 空目录 ≠ 无原音频。WebM/容器、WFDB DAT/HEA、压缩包都可能遗漏。每目录返回explicit状态：empty/archive_only/feature_only/unrecognized_format/decoded_audio等，不能统一叫无音频。
父级Spanish_logrado已出现_augmented_0及嵌套增强名“原始目录”本身也含派生版，增强样本不能随机跨训练测试。provenance与parent_id/augmentation标记；默认只取可追溯原件，身份不明阻止正式训练。
父级NCMMSC包含raw与raw_vad等；SLI含preprocess_a_data不能把所有子目录音频数当独立录音数；预处理/裁剪可能重复来源。representation_variant与origin_cluster；TaskSpec选择一个版本，不混原始与VAD版。
Respiratory_Sound_Database两个大小写目录各920很可能重复托管，仍需哈希确认；不等于1840条独立原始录音。文件哈希/解码哈希/来源映射，合并重复簇，原件保持不动。
父级Parkinson_3700有F_Con、F_Dys、wav_arrayMic_FC01S01等命名与TORGO形式强相似；“Parkinson”文件夹名不足以证明PD标签。隔离身份未确认库；先与TORGO对照文件内容/元数据，不纳入PD任务。
fresh UAspeech：Healthy含F02，Disorder含CF02；RAWDysPeech 1含F02UASpeech原始论文把F02列为构音障碍说话人；旧整理的Healthy映射至少存在强烈冲突。禁用旧二分类映射；从父级人员元数据重建并抽查，不能自动整体翻转就算修好。[R5]
Troparion父级Control39、Pathology15，旧表却写相反文件目录与网上整理表冲突，不由旧表多数投票决定。查Database_description与原始说明，核对类别语义/身份；先不作ALS主实验。
ADReSSo_2023内部实际有ADReSS_M_train及Greek test目录名可能与语料正式名称不符，不能模糊匹配后沿用ADReSSo协议。建议匹配D059但状态pending，保留官方train/test与sample身份，不当一个普通随机库。

还有计数一致性问题：报告中India_lung_sound总数757，但所列目录分组计数合计699；Parkinson_3700为3633但分组合计3635；TORGO和RAWDysPeech父/子多个卡片也有2条差值。本次可确认的是报告内部算术不一致，无法仅靠HTML判断原因。新扫描器必须断言“有效＋排除＋未识别＝发现文件”，且总数与分组口径一致。

本次不执行自动名称合并。DAC→DAIC-WOZ、EDAC→E-DAIC、Spanish_logrado→利马语料、lung_sound_3200→KAUH等都是候选映射。新增aliases.yaml可登记suggested/confirmed/rejected；正式manifest必须使用已确认canonical_id。模糊名称匹配只生成建议，不生成临床标签。
03 · 产品的五个模块

一个数据集只写一个Adapter；训练和结果模块保持不变。

① 数据适配每库一个Adapter
输出标准Record
② 任务编译标签/筛选/分组/split
输出TaskSnapshot
③ 视图与前端Hz/位置/时长/窗口
输出AudioBatch/FeatureBatch
④ 统一运行器选模型/训练/验证
输出标准预测
⑤ 统一结果聚合/指标/图表
输出RunBundle

你说的三层在这里展开成五模块：①②③属于数据层，④是模型运行层，⑤是结果层。任务编译与声音视图分出来，是为了不让Adapter偷偷决定随机划分、采样率或类别阈值。

模块允许知道什么不允许做什么新增数据集是否改它
Adapter该库目录/文件/元数据的含义、人员与录音关系、原标签训练、随机划分、调参、删改原件、计算测试成绩新增一个模块＋注册记录
TaskCompiler标准Record、TaskSpec、标签映射、人员关系与既有split阅读某库特有目录、靠文件夹数量猜疾病标签已有分类语义范围内不改
ViewBuilder统一AudioSource、允许区间、视图配置、分区train/val/test按数据集名if分支、按测试成绩改裁剪位置支持的声道/区间模式内不改
Runner/ModelRegistryAudioBatch/FeatureBatch、C、模型能力、训练配置读取EATD或MDVR路径规则、写私有指标只新增模型时注册插件
Evaluator/Report统一预测、class_order、评价单位、指标配置按数据集名调用不同准确率公式、静默删除失败任务分类新库不改；新任务类型才扩schema

“下游不变”的保证有边界：本次v0.1只支持单标签二分类/多分类，C≥2；回归、多标签、生存分析不假装自动兼容。新增普通分类数据集只增加Adapter＋声明式TaskSpec；若出现完全新音频容器，增加Decoder插件，这仍是数据插件而非改训练器。

参数不同不是代码逻辑分叉。CNN与MLP都由相同Runner选择，前端和预测器是模型插件的一部分；所有输出都为固定class_order的[B,C] logits或概率，Evaluator只按task_type与C分派。

04 · 必须落成代码的数据结构

用类型和验证器约束输入，不靠README口头约定。

# src/sddbench/contracts.py  —— 拟实现接口（Python类型示意）
@dataclass(frozen=True)
class SourceRecord:
    schema_version: str             # "1.0"
    dataset_id: str                 # canonical_id，不是本地目录名
    release_id: str
    recording_id: str               # 稳定标识；同名文件跨目录仍唯一
    relative_path: str              # 相对于本地绑定的数据根
    subject_key: str | None         # 经元数据确认的匿名人员键
    subject_basis: str              # metadata / directory / documented_one_per_person / unknown
    session_key: str | None
    source_recording_key: str       # 多麦克风/处理版本共用原录音来源键（有依据才填）
    variant: str                    # original / denoised / vad / augmented / unknown
    sound_kind: str                 # speech / phonation / ddk / cough / breath / auscultation
    elicitation: str
    labels_raw: dict                # 原始评分/组别，不先统一成“患病”
    allowed_regions: list           # [(start_s,end_s)]；whole-record可为[(0,duration)]
    audio_meta: dict                # sr/channels/duration/decode_status/content_hash
    provenance: dict                # source_file/row/label evidence/parent/channel/mic

@dataclass(frozen=True)
class TaskSample:
    sample_id: str
    recording_id: str
    group_id: str                   # 防泄漏单位，同人/关联来源连通组
    evaluation_id: str              # person / person-session / recording / event
    subject_key: str | None
    y: int                         # 0 .. C-1
    region_start_s: float
    region_end_s: float
    provenance: dict

@dataclass(frozen=True)
class TaskSnapshot:
    task_id: str
    task_hash: str
    class_order: list[str]          # 长度C，唯一顺序
    positive_class: str | None      # 二分类必需，多分类null
    evaluation_unit: str
    samples: list[TaskSample]
    manifest_hash: str

# 统一预测表PredictionRow：
# run_id, task_hash, split_hash, view_hash, fold, seed, split,
# sample_id, window_id, recording_id, group_id, evaluation_id,
# y_true, probs: list[float], valid_duration_s

字段的三个关键约束

  1. subject_key不能猜：人员暂未知可做scan/prepare，但人员独立正式任务编译必须阻塞。若官方证明一人一原录音，可生成匿名人员键并记录依据；文件数等人数不足以证明。
  2. source_recording_key不是万能身份：同人不同时间录音仍须同group；同一原录音不同麦克风/增强版本属于同来源簇。跨库已知同人需跨库映射，给ID加库名前缀不消除重叠。
  3. evaluation_id决定指标口径：同人标签一致时可按人聚合；纵向标签变化时用人—会话预测，但split/置信区间仍按人分组。事件分类以事件为单位，不能强行把不同事件标签平均为病人标签。

产物分层，程序生成而不是要求你手填

产物存什么什么时候改变
source_manifest.jsonlSourceRecord与排除/未解决记录；每条都有来源证据原始文件/标签元数据或Adapter代码改变
task_snapshot.parquet＋task.json筛选后的TaskSample、类别顺序、标签映射版本目标标签/纳入规则/评价单位改变
splits.parquet＋split.jsonsample_id/group_id对应fold和train/val/test；实际人数与完整性检查分组、划分算法/种子/名单改变
view_index.parquet＋view.json固定音频区间和窗口；随机位置已物化到索引采样率/观察位置/长度/窗口策略改变
run_bundle/配置、标准化器、checkpoint、预测、指标、日志每次实验有独立run_id，不覆盖

JSONL和Parquet是软件内部资产；审查XLSX仍只供人选库。这不是重新让你人工维护一堆互相矛盾的表。

05 · 新增数据集具体怎么写

把EATD和MDVR写成两个插件，检验“下游零修改”。

# src/sddbench/adapters/base.py
class DatasetAdapter(Protocol):
    dataset_id: str
    adapter_version: str
    def scan(self, root: Path) -> ScanReport: ...
    def prepare(self, root: Path, config: DatasetConfig) -> PrepareResult: ...

# PrepareResult = records + exclusions + unresolved + summary
# prepare只输出元数据与原件引用，不生成分类目录，不重采样，不划分。
# 注册表显式登记，不靠import时偷偷修改全局状态。
ADAPTERS = {"eatd": EatdAdapter, "mdvr_kcl": MdvrAdapter}

# 新库的提交范围：
# 1) adapters/new_corpus.py
# 2) configs/datasets/new_corpus.yaml
# 3) configs/tasks/new_task.yaml
# 4) tests/fixtures/new_corpus/ 的合成文件与标签
# 5) docs/datasets/new_corpus.md
# Runner / Evaluator / 既有Model不得因新增普通分类库修改。
插件实际目录解析规则标签与身份不能做的推断
EatdAdapter从父级EATD/EATD-Corpus查找人员目录；识别positive/negative/neutral及_out版本；检测并排除旁文件保留原目录完整键；读label.txt/new_label.txt及官方划分信息，输出原始SDS与可用记录不将t_7与v_7自动当同一个人，也不能未经元数据确认就认不同人；不把positive当抑郁阳性标签。
MdvrAdapter从父级Parkinson_KCL_2017读取ReadText/HC、ReadText/PD；对话保留为另一个elicitationIDxx作为库内人员线索；HC/PD映射由官方README和目录/文件名交叉验证；保留严重度字段但不作模型输入H&Y、UPDRS与pd/hc字串会泄漏标签，绝不作为声学模型特征；文件名不传给网络。
以后EasyCall人员目录→Sessione→命令词，统计两组共同prompt集合用原人员信息确认病例/对照；筛共同命令词，全部session按人归组不是318疾病类别；不从每个session新造一个人。
以后UASpeech/TORGO选择一种明确mic；保留subject/session/prompt/utterance源说明与身份表确认组别；跨任务/麦克风处理同人旧fresh二分类标签不当真值；不能将143290个麦克风文件当143290个人。

06 · 任务编译与划分

目录组→有语义的任务→固定人员清单，必须分三步。

TaskCompiler.compile(records, TaskSpec)依次：筛选声学类型和版本→检查source/group证据→按显式规则映射标签→检查同evaluation_id标签一致→生成样本表→输出类别/人数/排除原因；未知标签或身份直接列unresolved。正式train不能静默drop未知样本。

Splitter.build(TaskSnapshot, SplitSpec)只看人员键和允许用于分层的训练标签，生成固定split。对相同group、已知来源簇、增强parent、访次进行跨集合断言。简单二分类可以先对每人一行的表做分层拆分，再广播到音频；不能让片段数多的人影响分层比例。

# configs/protocols/demo_grouped_v1.yaml
id: demo_grouped_v1
mode: grouped_holdout
train_fraction: 0.60
val_fraction: 0.20
test_fraction: 0.20
seed: 2026
stratify: label_at_evaluation_unit
require_all_classes: true
min_groups_per_class_per_split: 2
on_infeasible: error            # 不自动回退文件随机划分

# 发表用另注册subject_cv_v1：
# 外层按人3折(可行才用)，各外层train内再划分val；
# 复杂多标签/纵向数据须专门分层策略，不套上面一人一标签规则。

Demo的60/20/20仅用于闭环验证，和正式的外层分组交叉验证是不同protocol_id。原官方split可靠则优先复现；无公开测试标签可登记另一套本地研究协议。不要为了界面“一键”把不可行划分自动改成按文件随机。

scikit-learn提供StratifiedGroupKFold等成熟工具，仍需要你在实际输出上断言人员互斥与类别覆盖；它不是医学数据自动去重器。[R3]

07 · Hz、长短、位置怎样统一控制

这组参数只在AudioView变化，不写进每个Adapter。

数据适配完成后，原音频保持只读。ViewBuilder.plan(snapshot, splits, ViewSpec)输出确定的窗口索引；AudioReader.load(window, root_binding)负责加载、选通道、裁剪、重采样及返回有效长度。裁剪坐标统一使用原始文件秒数，不用各库不同采样点数。

参数v0.1取值/语义关键约束
target_sr_hz16000；以后可以8000/16000/32000模型capabilities不支持该Hz则plan报错；不偷偷升采样。区分接口采样率与有效带宽。
bandwidth_hznull；可选4000Hz受控降带宽16k音频→8k→16k等操作明确写入视图；与直接喂8k接口不同。原8k数据不能用于高频恢复实验。
observe_secondsall 或固定秒数，如16指每条合格样本实际听多少时间，不是编码器窗口大小；短录音只听现有部分，不循环填充。
anchorhead / center / tail / fraction / fixed_random位置仅在合法目标人区间内选择；fixed_random由sample_id＋view_seed决定并保存，不每次重跑重抽。
window_seconds4.0；stride_seconds默认等于window_seconds总观察16秒可分4个4秒窗；2秒或8秒窗口是上下文实验，不改变总观察预算。v0.1主轨道强制stride=window，避免重叠窗口重复计时；以后开放重叠需另定覆盖权重和协议。
tail_min_seconds0.25（初始建议）小于该阈值的末尾残片排除并记录损失时长；其他残片保留、补零、mask。所有方法共用同一索引。
channel_policyselect或已证明同一声音的mean采访者/病人或音频/EGG不同通道不能平均；mic文件版本也要先在任务筛选中固定。
amplitude_policynone；模型专属必需归一化在ModelSpec声明不一边删除停顿一边研究停顿；VAD/降噪以单独variant处理，初版不加。
train_position_policy与eval相同固定索引v0.1不做random_per_epoch以保持缓存一致；以后新增只限训练的在线采样，必须记录种子/epoch。

具体走一遍

假设一条已确认目标人录音为20秒，设置observe=16、anchor=center、window=4、stride=4：观察区间为[2,18]，窗为[2,6]、[6,10]、[10,14]、[14,18]。把anchor改tail，仅变为[4,20]及相应窗口；模型和Evaluator无需修改。若有采访者区间，按合法区间策略处理，不跨不连续访谈轮次假造连续时间。

若录音只有3秒而window=4，返回有效3秒＋必要补零。模型前端只能对有效帧求统计量；单纯把补零算进去会让时长变成无意特征。骨干最小样本长度与模型mask行为须验证；无法支持的极短片段标blocked或按明确政策排除，不能临时改任务。

MFCC＋MLP80→128→C；ReLU；dropout=0.2hidden_dims=[64]/[128]/[256]、dropout、lr、weight_decay不能因新库改train.py；缺失输入自动报错而不是切换模式
Mel＋CNN64 Mel；3×3卷积通道32/64/128，池化后global readout→Cchannels、kernel、dropout、Mel频带数有效长度/卷积输出mask；不同长度不展平到任意巨大FC
冻结SSL＋线性头指定检查点revision；最后层；masked mean→Ccheckpoint、layer、pooler、head_dims；先固定mean输入Hz符合能力声明；冻结时eval()＋no_grad()；归一化明确
未来方法新增pooler或adapter组件，而不重写评价脚本后续研究二的统计/注意力聚合、研究三的共享模块预测表仍[B,C]，同Evaluator评估；任务类型变化需新schema

传统前端25ms窗、10ms hop、16k下FFT512、64 Mel等可作起点，但必须同时锁定Mel尺度、log变换、DCT、窗函数、中心填充、库版本。任意输入Hz变化时以毫秒计算实际窗长/步长，并显式检查FFT容量与fmax≤Nyquist，不能沿用不适配的硬编码。

初版神经模型可用AdamW、lr=1e-3、weight_decay=1e-4、batch=32、最多80轮/5000更新、val patience=10作为先导配置。正式预算在少量训练/验证检查后锁定；不能把这些值称医学最优参数。跨模型有相同候选次数不等于相同GPU成本，成本另报。

训练数据单位：两种政策不要混在一起

v0.1选择全部固定窗口＋训练损失权重：同评价人员/会话的所有片段总权重为1；人员下录音等权、录音内窗口按有效时长归一。分类不平衡先保持自然人数分布并用balanced accuracy；如需类权重，基于训练人员计算、所有方法一致，不同时又无说明过采样。v0.2可换人员均匀采样，但单独protocol版本，并记录每任务实际曝光。

10 · 一个run内部的准确调用顺序

数据准备只做一次，配置实验按指纹复用。

def run_one(plan: ResolvedPlan) -> RunBundle:
    validate_plan(plan)                         # key/schema/capability/phase
    source = load_prepared_manifest(plan.manifest_hash)
    task = load_task_snapshot(plan.task_hash)
    splits = load_split_snapshot(plan.split_hash)
    view = load_or_build_view(task, splits, plan.view_spec)
    assert_no_group_or_parent_leakage(task, splits)
    loaders = make_loaders(view, plan)          # train/val/test明确分开
    model = MODEL_REGISTRY[plan.model.id].build(plan.model, len(task.class_order))
    fitted_transforms = fit_train_transforms(loaders.train, plan)  # 只看train
    loaders = apply_frozen_transforms(loaders, fitted_transforms) # 三个集合用同一train拟合结果
    fit_result = model.fit(loaders.train, loaders.val, context=plan.context)
    freeze_selected_config_and_checkpoint(fit_result)
    predictions = model.predict(loaders.test, fit_result.best_checkpoint)
    verify_prediction_coverage(predictions, view.test_windows)
    eval_predictions = aggregate_predictions(predictions, plan.aggregation)
    metrics = evaluator.compute(eval_predictions, plan.task_contract)
    return bundle_writer.commit(plan, fit_result, predictions, metrics,
                                fitted_transforms=fitted_transforms)

# 实际实现将train-valid与test作为可单独调用阶段；
# 若task未准入、test未解锁、缺任何应预测行或重复预测，禁止完成标记。

窗口→录音→评价对象的固定聚合

先对softmax概率而非logit/硬标签聚合。窗口按有效时长归一，得到sample/录音概率；同一evaluation_id多条合格录音等权平均（或任务预声明的策略），最后按二分类阈值/多分类argmax出预测。分类标签应在该评价对象内一致，否则TaskCompiler必须报错。评价单位不同允许注册不同策略，但公式实现不能按数据集名分叉。

同样的metrics引擎可以同时输出recording与subject指标，必须以unit明确命名。主比较只比同一task_hash、split_hash和主评价单位下的模型；不把录音accuracy和人员accuracy放一列混平均。

缓存三类，失效边界分别定义

缓存key至少包含什么不能做什么
解码/视图源文件内容哈希、region、声道、解码器/重采样版本、观察/窗口配置改采样率/位置仍复用旧wave；只凭文件名找cache
冻结前端/SSL帧view_hash＋前端参数/检查点revision/层/精度/归一化更新骨干LoRA后继续复用旧帧；训练dropout开启提取永久特征
拟合变换训练split_hash＋特征key＋标准化/PCA/选择算法配置用全数据拟合Scaler再称按人无泄漏；跨CV折共享有监督变换

调dropout只重训头，通常复用冻结特征；改MFCC维数重算传统特征；改observe位置重建view；改split重做训练拟合变换。原始解码可跨split复用，因其不学习标签/总体统计。冻结骨干先串行提取，补零mask/GroupNorm导致批量不等价时不能简单靠GPU批量加速。

11 · 结果层完整指标规范

该有的都算，但“不适用”必须显式返回NA与原因。

所有分类任务共用一个ClassificationEvaluator，底层调用锁定版本的scikit-learn。返回结构固定；二分类/多分类、评价单位与类别集合决定数学定义，不由数据集私自决定。[R1] [R2]

输出二分类多分类/统一约定
样本/人员规模n_units、n_groups、每类support、排除/未覆盖数类别顺序固定；显示计划与实际数量，不允许漏样本后只报高分
Accuracy按阈值的正确率argmax正确率；同时显示class_support，不能靠多数类掩盖
Balanced accuracy两类recall等权各类别recall等权；预期类别未覆盖时主指标NA，避免静默变更类别集合
Precision / Recall / F1正类值＋每类值＋macro/weighted每类、macro与weighted均输出；micro可额外输出但对单标签常与accuracy重复
Sensitivity / SpecificitySensitivity=TP/(TP+FN)；Specificity=TN/(TN+FP)按每类one-vs-rest列；分母0则该率NA，不填0冒充有效
ROC-AUC使用指定positive_class的概率，不使用0/1预测固定OVR macro为主并逐类；可附OVO macro。某预期类别缺失则完整macro-AUC为NA＋原因
PR-AUC主命名average_precision，另存PR曲线逐类OVR AP及macro；明确AP不是PR曲线梯形积分的同一个值；类别缺少正/负支持时NA
Confusion matrix固定2×2顺序＋TN/FP/FN/TP固定C×C顺序，另存按真实类归一版本，零support行标注
Log loss / Brier概率clip到已声明epsilon；正类Brier作为概率误差多分类log loss；多分类Brier若实现须新明确定义，v0.1可NA
曲线与图ROC、PR、混淆矩阵、loss/val学习曲线多分类逐类ROC/PR可折叠展示；无定义不画假曲线
不确定性人员成簇bootstrap，配对比较同一测试人员Demo可不跑CI但标not_requested；正式关键结果固定重抽样次数/seed，报告有效bootstrap次数
成本总参数、可训练参数、提取/训练/推理时间、峰值显存、设备时延说明是否包含解码/特征提取、batch大小与预热；不能混用不同测量口径

零分母、单类与缺样本政策

Precision/F1可用zero_division=0保障报告结构稳定，但必须标出undefined类与support；这不意味着Specificity/AUC也填0。AUC依赖正负支持，单类test返回null与single_class_y_true。缺失类别时全类别主balanced accuracy/AUC不进排名，其他能定义的指标保留并警告。非有限概率、向量长度≠C、行和偏离1、重复window_id、标签不一致应fail，不是NA继续出榜。

二分类默认阈值0.5；若用验证集优化阈值，应保存threshold.json并另标协议，不在测试集调。多分类主轨道argmax；概率校准、逐类阈值属于另外的训练/选择步骤，不静默开启。macro/weighted、正类定义、计数单位全写入metrics.json。

全套件结果固定怎么出

results_long.parquet按run/task/model/fold/seed/view/metric一行；benchmark_table.csv按任务×模型汇总；suite_report.html展示覆盖率、每任务主指标、成本和配置差异。只有相同task/split/评价单位才允许直接模型排名；跨任务等权平均必须使用相同预声明任务交集，失败任务在分母与覆盖中可见。

不用每个数据集手写accuracy.py，也不用从终端复制数字。对保存预测重新运行Evaluator应重现原指标（容差内）；这是首版最重要的验收之一。

# 2. 任务编译→审计→划分，关键身份/标签未明会blocked
python -m sddbench task build --task mdvr_pd_read_v1
python -m sddbench task audit --task mdvr_pd_read_v1
python -m sddbench split build --task mdvr_pd_read_v1 --protocol demo_grouped_v1

# 3. 展示解析计划，再训练；test阶段单独执行
python -m sddbench plan --config configs/experiments/demo_mlp.yaml
python -m sddbench run --config configs/experiments/demo_mlp.yaml --phase train-valid
python -m sddbench evaluate --run <run_id> --split test
python -m sddbench report --run <run_id>

# 4. 已锁定配置的一键闭环与批量执行
python -m sddbench run --suite core_demo_v1 --phase all --resume
python -m sddbench sweep --config configs/sweeps/mlp_sensitivity.yaml --dry-run
python -m sddbench sweep --config configs/sweeps/mlp_sensitivity.yaml --resume
python -m sddbench summarize --suite core_demo_v1

一键all不是跳过审查：仅当任务已准入、split已锁定、测试阶段允许、计划能力校验通过才执行。研究开发阶段默认train-valid；正式发布配置再允许all。一键套件遇到某job失败可继续其他独立job，但最后退出状态与summary必须显示失败，不能“忽略失败算成功”。

新增库的用户流程

写Adapter和TaskSpec→注册→prepare→audit通过→放进suite.tasks。然后同一个run/sweep/evaluate/report自动适用，不改平台核心。若新库仍是普通分类但迫使修改Trainer/Evaluator读取其目录，视为架构验收失败，回到Adapter设计修正。

tests/{unit,integration,fixtures}/、docs/契约测试、小合成数据、数据卡与实现说明

首版错误码

错误码含义与动作
E_DATASET_ID_UNCONFIRMED名称匹配未确认；允许scan，正式prepare/task需绑定canonical_id
E_LABEL_UNRESOLVED阈值/标签来源未知；停止该任务，不猜
E_GROUP_UNRESOLVED / E_SPLIT_LEAK人员不清或跨集合重叠；停止正式训练
E_AUDIO_DECODE / E_VIEW_EMPTY音频无效或有效区间为空；进入排除清单，重编任务需确认并改变hash
E_MODEL_INCOMPATIBLE采样率/层/输入形状不支持；plan阶段拒绝，不自动偷偷改参数
E_PREDICTION_COVERAGE缺少/重复预期预测；不标succeeded，不出正式主表
E_CONFIG_MISMATCH / E_CACHE_STALE恢复配置不同或cache不匹配；拒绝复用，输出可重建步骤
E_METRIC_UNDEFINED单类等指标不适用；metric-level NA不是整个训练失败
E_OUT_OF_MEMORY记录stage/配置；不静默删长音频或降低输入时长。物理batch变化也需记入运行记录

快照在临时文件写完后原子提交，manifest/split已锁定不原地编辑。OOM改batch与梯度累积可能改变BatchNorm行为，不能一句“有效batch没变”就声称完全等价。首版串行调度、单GPU即可；并行多GPU/网页后台不是第一阶段要求。

首版必须存在的12个测试

  1. 每条manifest ID唯一、路径相对根且可定位；源metadata冲突明确报错。
  2. 增强parent/同人多会话/多麦克风不跨split；与任务标签无关的元数据不进模型输入。
  3. EATD positive/negative任务词不会被当疾病标签；t_/v_人员规则由fixture明确验证而不是随意去前缀。
  4. 相同样本/head-center-tail产生预期秒区间，Hz变化不改变原始坐标。
  5. 4秒窗/3秒短音频/小尾窗处理符合配置，有效长度与排除时长一致。
  6. 二分类/三分类输出概率C维、类别顺序固定；C自动来自任务。
  7. 小型金标准预测的accuracy、macro-F1、specificity、AUROC与锁定sklearn定义一致。
  8. 单类test AUC返回NA＋原因；缺类别主指标不能悄悄出排行榜。
  9. 改变view/checkpoint/layer必使相应cache失效；训练Scaler不看val/test。
  10. 预测缺一行/重复一行必须不能标记succeeded；结果能由保存概率重算。
  11. 第二Adapter加入后共享引擎不修改；重命名本地数据根不改变task内容身份。
  12. 中断恢复边界清楚；相同config禁止不同内容覆盖同run_id，suite保留failed/blocked。

这些测试保护的是论文结论与可复现性，不是为了堆测试数量。真实数据抽查是另外一层，合成夹具不能证明真实标签正确。

17 · 这个Demo怎样变成第一研究块

先验收平台，再做受控实验，不能把软件功能直接当科学结论。

实验怎样在平台里表达保持不变产物
默认基线suite中选任务×LR/MLP/CNN/SSL-linearsplit、观测区间、标签、评价单位主矩阵、成本、覆盖率
采样率/带宽只换ViewSpec，区分target_sr与bandwidth模型接口支持、人员清单和其他参数频带敏感性曲线，不做8k升采样恢复宣称
总时长/位置observe_seconds与anchor单因素；同视图供所有模型窗口/模型/人员/标签观察预算与位置对成绩影响
上下文窗口window=2/4/8秒，同时固定observe=16等真实听到的总音频区间编码上下文与聚合粒度影响；短录音不参不可能设置
容量/dropout换ModelSpec相应一项前端/数据view/split参数敏感性与同预算选择后的排名
默认对调优固定default对预声明候选search，每外层train内val选外层test人员与主指标结论是否依赖任意默认设置
人员划分诊断另建文件随机diagnostic protocol尽可能匹配规模/任务/类别，承认测试人群差异泄漏风险分析；文件随机结果不进正式榜

先两个真实任务证明可行，再扩到其他可信语音库。报告缺陷已经说明为什么不能现在一键跑二三十库：父级标签尚有目录误读、镜像、增强、处理版本和身份问题。平台自动化的是已明确定义的实验，不是自动猜出可信标签。
